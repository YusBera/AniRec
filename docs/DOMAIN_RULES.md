# Domain Rules

These are the rules the product is judged on. Where the current code violates
one, that is a defect to be fixed, not a precedent to follow.

---

## Evidence

Never invent a score, rating, count, date, cover image, synopsis, or explanation.

A value the system does not have is shown as unavailable, in words. Not zero, not
a dash that reads as zero, not a plausible substitute.

Every number on a surface must trace to a value the API returned. The frontend
does not recompute scores, matches, or contributions.

A demonstration is not evidence that a live capability exists. Sample payloads
must stay visibly labelled, must be opt-in, and must never be written into a real
profile directory.

---

## Explanation

An explanation must reconcile with the score it explains.

* If contributions are shown, they sum to the displayed score.
* Negative contributors are shown. Filtering an explanation to positive terms
  only, while a negative term is the largest single signal, is dishonest output.
* A reason string must come from the ranking that produced the score. A reason
  generated by one model attached to another model's ranking is fabrication.

Signal labels are typed. A studio is not an "interest", and a source medium is
not a genre. Where the underlying data mixes these, normalise before display and
keep the raw value separately for debugging.

A ranking that cannot explain itself must say so rather than borrow an
explanation. The ONNX sequence engine has no additive contributions; it is
explained by counterfactual removal of the reader's own history
(`DECISIONS.md` D-012), which must never be presented as shares of the score.

---

## Recommendation Eligibility

Do not recommend a title whose prerequisite the reader has not consumed. A
sequel, a later season, or a recap film of an unwatched story is a defect. The
shared final eligibility policy enforces the installed bundle's verified direct
prerequisites for primary and fallback ranking. Broader franchise and recap
coverage remains incomplete until the collector relation graph is served.

Do not recommend a title the reader has already completed, dropped, or set aside.

Media type is part of eligibility. Music videos, commercials, and promotional
shorts are in the catalogue and are not recommendations.

Candidate generation must not be a popularity prefix. A reader whose taste sits
outside the popular head must still be reachable.

---

## Scoring Honesty

Do not present an uncalibrated model output as a percentage. A percentage claims
a meaning; if the number cannot support that meaning, use a rank, a tier, or a
described strength instead.

If a match figure is shown as a percentage, it must be calibrated against held-out
behaviour so that the number means something a reader could check.

A personal match and a community rating are different claims. Do not blend them
into one figure presented as personal.

Sparse history is a state, not a low score. Below the evidence threshold, the
surface says the system does not know enough yet. The view model already carries
an availability flag for this; the heuristic path never sets it.

A feed must not be ordered by a discarded ranking. If a selection policy
randomises, its cost is measured and stated, and the control that governs it is
labelled for what it actually does.

---

## Diversity

A feed is not ten entries from one franchise. Ranking quality and feed quality
are different things, and next-item accuracy does not measure the second.

Any change that removes a randomisation step must add an explicit diversity
mechanism in its place.

---

## Identity and Data Isolation

Account scope is derived from authenticated server-side context, never from a
request field. A `profile_id`, account id, or username in a payload is a hint to
validate, not an authorisation subject.

A reader's list data, taste profile, saved decisions, and activity log belong to
one account and must never be reachable from another.

Item identity is internal. External ids (MyAnimeList, AniList, others) are
mappings onto it.

---

## Third-Party Data Handling

Anime content is obtained through an official API or from the existing collector
snapshot. Do not add scraping from this repository.

Per-user third-party tokens are credentials. They are never logged, never
returned by an API response, and never written to a file in plain text.

The constraints in `docs/PROJECT_DEFINITION.md` bound what may be redistributed
and what may be monetised. A feature whose viability depends on an unresolved
question there is flagged, not shipped quietly.

Activity and telemetry are opt-in, local by default, retention-bounded, and
exportable by the person they describe. Collecting data that no one can read back
is not instrumentation; it is storage.
